Qualidade de software · Relatório de atividade

Testes automatizados na Biblioteca Online

A atividade acompanha a consulta ao acervo desde a resposta da API até a tela do leitor. O projeto usa Node.js, Express e PostgreSQL. A interface permite entrar na conta, cadastrar livros e atualizar a lista.

O que foi testado

Backend. Três testes chamam o controlador da rota GET /livros. Eles conferem se a API devolve os registros com status 200, se aceita um acervo vazio e se responde com status 500 quando a consulta falha.

Frontend. Dois testes carregam a página e seu JavaScript no jsdom. O primeiro verifica o título e o estoque de um livro e aciona “Atualizar Lista”. Quando a segunda consulta retorna vazia, a tela substitui o livro pela mensagem de acervo vazio. O segundo verifica a orientação para entrar na conta quando a API retorna 401.

Resultado e publicação

Na execução local, os cinco testes passaram. O GitHub Actions instala as dependências e executa a mesma suíte. Na branch main, a etapa seguinte envia ao Render o identificador do commit aprovado e acompanha a publicação até o serviço ficar disponível nessa versão.

Dificuldades e soluções

O repositório original tinha duas versões do backend. A branch API-online forneceu a implementação compatível com o PostgreSQL. Para testar falhas de consulta de modo repetível, a suíte substitui temporariamente a chamada ao banco. Outra dificuldade estava no endereço fixo do frontend, que apontava para localhost. O uso de uma rota relativa permite que o navegador encontre a API no endereço publicado.
